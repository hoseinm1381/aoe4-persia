# Persian Blacksmith — unbuilt source draft

Only recipe and editing directions have been authored. No Blender operation, saved master, texture generation, geometry validation, state/LOD production, cook or integration is claimed.

The original plan combines a heavy open fire chamber, one hollow masonry smoke flue, a deep handling porch, supported benches/anvil and a separate tool/fuel store. A2 emphasizes open timber handling; A3 divides hot/cold work with an enclosed store and inspection bench; A4 adds a cool finishing bay and taller fitted store. These are artistic expansions across the three existing native bodies, not new gameplay tiers or a claim of excavated workshop plans. The square smoke passage remains open through the hood and flue; the fire bed is matte charcoal without invented glow/smoke behavior.

Historical direction comes from [Iranica, Ahan](https://www.iranicaonline.org/articles/ahan-iron/) and [Allan, Nishapur metalwork](https://resources.metmuseum.org/resources/metpublications/pdf/Nishapur_Metalwork_of_the_Early_Islamic_Period.pdf), as summarized in `research/persia_buildings/history/ORDINARY_BUILDING_REFERENCE_GUIDE.md`. The sources support craft context; specific furnace, bench and roof dimensions are original game-art proposals, not exact historical measurements. No modern ethnographic bellows chronology is asserted.

`recipe.py` exposes the House-style `foundation(key)`, `first_room()`, `architecture()`, `props()`, `detail()`, `build_body(key)`, `root(key,state,lod)`, `show(...)`, `ANCHORS`, `CONTRACTS` and `write_anchors()` interfaces. `reset_owned()` is explicit and restricted to this family's literal prefix. The only admitted keys are A2/A3/A4. Every part is a separate closed mesh through the shared source runner; draft tags and named bearing contracts remain available for parent checks. No recipe code executes a build, save or cleanup on import. Parent must first supply original 2048 albedo/normal/roughness/metalness/owner-mask PNGs at `textures/<kind>.png`; placeholders and stock textures are not generated here.

The body consumer is `ps_building_tech_unit_infantry_control_sul`. `campaign` and `default` are serialized private variants; `cordoba` and `xp3` remain official-parent inheritance candidates. Each exact source use, attachment and native stamp is retained in the recipe constants from `PRIMARY_BODY_HANDOFF.json`. There is no A1 source body.

Authoring uses projected **stamp coordinates**, deliberately spanning a proposed complete work court. It is not confined to the native primary body alone. `NATIVE` records primary and conditional complete-compound bounds from `SOURCE_CATEGORY_COMPOUND_BOUNDS.json`; conditional bounds do not prove simultaneous native visibility, a placement footprint or collision clearance. The recorded inverse body stamp matrix targets the decoded/projected resource frame and must be applied exactly once by a future adapter. No transform is applied by this draft.

The existing stock bellows is reserved rather than replaced or duplicated. Its exact stamp matrix, rest-bound interval and instance indices (3/33/37) are retained. The reserved box is a source review exclusion, not its animated swept volume or a verified nozzle socket. Parent must inspect the native graph/rig and mechanism connection before reconciling the new fire block; preserving resource identity alone does not prove a functional connection. Existing layout markers are bone-local until their native skeleton frame is resolved. Native props and backdrop owners remain dependencies; this draft does not authorize deletion or duplicate attachment activation.
