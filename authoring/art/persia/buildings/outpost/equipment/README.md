# Outpost native equipment source preparation

All 8 standard legal configurations are mapped in `source-contract.json`, keyed
`wood__none/arrowslits/springald/cannon` and
`fortified__none/arrowslits/springald/cannon`. Native body keys are exactly
`A1Basic` and `A1Fortified`. No new gameplay tier or legal powerset is invented.
Inherited baseline garrison fire remains separate from researched emplacements.

Parent execution, after the serialized family batch:

1. Run `native_equipment.py` in an unsaved factory Blender process. It needs no
   Garrison extension or decode: it reads the exact retained public native import
   libraries, creates exact editable upgrade component meshes from cached plans,
   retains the basic seven-root reference forest, and preserves original material
   nodes/images from authoritative native `misc` identity. It writes the bounded
   `native_equipment_inputs.blend` and JSON receipt.
2. Run `build_configurations.py --render --render-heavy` in another factory process. It reads the
   current `../outpost.blend` healthy LOD0 original architecture, creates 248 unique
   editable assemblies (8 configurations x31 source states/LODs), appends exact
   lifecycle-selected equipment and source reference hierarchies, then saves `outpost_configurations.blend`,
   `configuration-checkpoint.json` and consistent healthy/heavy/ruin source previews per configuration
   under this subdirectory. No original body/recipe/family master is modified.
3. Inspect each configuration, especially attachment/support relationships and
   combined arrow components. This is a source checkpoint, not acceptance. All31 original body compositions are retained per configuration. Exhaustive
   lifecycle/LOD checks remain deferred and are never described as passed.

Cold factory API:
`append_configuration(collection, id, matrix=None, lifecycle='healthy',
collapsed='false', allow_unqualified_source_inspection=False)`.
The last flag is explicit: it permits inspection of intact raw native components
whose original zero-area faces fail applied-normal fidelity; every affected
component remains marked unqualified. The 8-configuration checkpoint deliberately
uses this inspectable-source option, retaining errors in the receipt. No original
triangles or normals are deleted or silently repaired.

Only native upgrade fragments in mesh2/group0 are selected; original main/roof
tower groups never enter the compiled equipment library. Complete original
native source libraries, raw RGM/RRGeom/RGO/material/media, selectors, parent
reference TRS, graph/action dependencies and stamp alternatives remain retained
and hashed externally. Combined arrow fragments still need visual classification
of their attached architectural content; a native fragment name is not proof
that all of it is moving weapon geometry.

Basic has seven independent native reference bones with qualified source inverse
bindings. Graph evidence supports collapse/repair reference inspectability; it
does not prove aiming/recoil motion. Fortified has ZERO native skeleton bones and
unbound source fragments; no matching bone forest is fabricated. Root markers
are projected as model-reference empties; bone-local/unknown-frame records are
quarantined. Geometry-free cannon child contributes zero triangles but retains
its original muzzle/FX owner. No new clips or invented playback.

Known source gaps remain explicit: absent combat-requested markers, fortified
muzzle/component height differences, actual original-body fit/supports, optional
source sweep/poses, combined-arrow shell content and affected original zero-area
face normal fidelity. No guessed marker aliases, automatic muzzle snapping or
static pretend cannon/springald proxies are added. Actual native-game behavior,
export/cook and package gates are deferred.

Existing compiled/configuration blends are overwritten only when their receipts
match current file hashes. Manual edits stop regeneration. Configuration saves
disable `.blend1` versions in the parent-owned factory process. Actual rendered
preview SHA-256 and byte counts are recorded; no worker render was executed.

The source-state route now authors all248 assemblies in 8 scenes, each with31
state/LOD collections and healthy LOD0 visible by default. `--render` creates
8 healthy previews; add `--render-heavy` for damage5 and ruins too (24 total).
LOD1/2 retain complete exact native equipment geometry; ratios are explicitly
unqualified. Original body state/LOD geometry comes from the current source master.

All20 native construction states construct00..95 were proven to select zero
equipment in ALL8 configurations. First3 authored construction stages therefore
contain empty equipment. The authored finish stage uses exact healthy equipment;
there is no invented construct100 state or native progress/HP wiring. The exact
248 slot mappings and proof are in `state-slot-preparation.json`.

inspectable. Original small slitted gallery guards carry the active arrow upgrade
appearance, with the existing body roof retained. The guards are seated at basic
upper breastwork6.65 / fortified gallery5.52 and leave when their platform fails.

Heavy/ruins configurations omit intact springald/cannon compounds from the visible
source composition to avoid the observed doorway/wall intersections. Exact native
lifecycle-selected alternatives remain inactive and inspectable, at their raw
reference frame. This is an explicit authored source visibility choice, not native
visibility/collapse playback. No invented clip or native pivot change.

A library template is read once per native body and materials/images are shared;
every state receives unique editable mesh and reference-armature data.
