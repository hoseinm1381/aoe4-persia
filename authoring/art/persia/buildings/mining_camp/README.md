# Mining Camp healthy architecture draft

Status: original geometry recipe draft only, not a built or accepted asset. No Blender process, render, native extraction/decode, export, cook, package or gameplay edit was performed for this task. Parent inspection and adaptation follow House acceptance.

The source/native inventory identifies one shared existing `com_mining_camp_combined` body, with no age suffix. `BODY_KEYS=('Shared',)` deliberately supplies only that body. The current private default/campaign branches share it; official-parent Cordoba/xp3 remain separate inheritance candidates. This is not permission to add new age tiers.

The plan has a low, heavy west ore/tool store with a small brick barrel roof, compact front retaining bins, and a separate east sorting/washing shelter. A low legged bench and open-bottomed stone-lined trough provide work surfaces; a runnel drains to a shallow contained sediment dish. Mineral stock stays in its bins. The density and short travel distances contrast with Lumber's long open log stacks. Earth/plaster, brick vaulting, coarse stone and limited exposed timber provide regional identity. No blue portal, dwelling court, human figures, excavated shaft or modern headframe is included. This is original functional game architecture informed by reference-guide sheet 5, not a measured medieval Persian mine plan.

Projected cooked donor rest bounds are x[-6.13671875,1.3388671875], y[-5.078125,2.8828125], z[-4.46484375,5.30859375]. The static plan uses approximately x[-5.72,.70], y[-4.65,2.34], z[-.03,3.12], before the native stamp and actor scale. The native stamp rotates about 15 degrees and translates by projected (+2,+2,0). Its exact matrix remains in inventory. Negative/high rest vertices are not an animated sweep or a reason to create deep terrain holes. Parent must verify the generated envelope against qualified posed/native fitting evidence.

Measured stock complete-compound healthy LOD0 target/cap is 6998 triangles. The recipe aims below that cap without padding detail to reach a number. Mesh triangle totals, topology, UVs, named contacts, collision, scale, native fit and appearance remain unverified until the parent builds it.

An offline Python mock of the existing runner's coordinate formulas passed syntax, all 72 planned vertical contact records, and contact-point containment within both named parts' planned bounds. It predicts 90 parts, 1448 triangles and bounds [-5.72,-4.65,-.03] to [.70,2.34,3.0991]. This is recipe mathematics only: no Blender mesh datablock, normals/manifold/UV behavior, materials, render or native pose was tested. In particular, bounding-box containment is not final proof of a diagonal joint.

The native seven-bone dependency proves a movable lifting assembly is actually applicable: `bone_root -> bone_crane_turn -> bone_crane_tilt`, with stones/orientation and crate/orientation branches below the tilt bone. The small supported derrick in this source is an explicitly static healthy composition proxy, not a native rig replacement. Its pivot, boom, stay and hanging lift line have named contact plans, but the original native owner, bone transforms, socket frames and mechanism behavior must be retained/rebound by the parent. `NATIVE_DEPENDENCY` records local native paths/hashes and the shared rig inventory. No new clips, playback, retargeting, world-space sockets or matching posed mechanism are claimed. If the retained native crane is presented alongside this proxy during inspection, hide the proxy first to avoid duplicate mechanisms.

House-compatible API: `CURRENT`, `root`, staged `foundation/first_room/architecture/props/detail`, `build_body`, `ANCHORS/CONTRACTS`, and `write_anchors`. All pieces carry role, construction stage and structural group. Vertical contacts use the existing House contract form; nonvertical derrick joints are named numerical endpoint interfaces in anchors. The trough is a real open container, not a water-colored block. The secure store is an occupied shell with a recessed door, not a solid decorated cube.

The existing shared runner expects original future 2048 maps at `textures/albedo.png`, `normal.png`, `roughness.png`, `metalness.png`, `owner_mask.png`, using its 4x4 surface tile convention. No textures are created here. Owner cloth is small and bracket-supported. Local wear sits at the bin discharge, sorting bench, store threshold and trough outlet; it is purposeful and deterministic.

Remaining gates: parent serial healthy build, six-side/underside solid inspection, contact and doorway/bench/crane-clearance checks, normal/manifold/UV/triangle verification, then state/LOD/native-fit pipeline adaptation. Existing construct_00..95, healthy/damage/ruins/preview/targeting and native physics owners are still required contracts.
